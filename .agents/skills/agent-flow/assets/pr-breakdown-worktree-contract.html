Contract

Default Split Rules

  • One responsibility and one reviewer mental model per PR.
  • Each PR is independently reviewable, buildable, testable, and deployable.
  • No PR depends on code that is only promised in a later PR.
  • Generated files and tests are excluded from size estimates but included in validation.

Bypass Rules

  • Record the user-approved reason for a coarse or single-PR path.
  • Call out residual review risk and validation implications.
  • Keep a fallback split ready if the implementation grows.
  • Never use bypass to hide missing decisions or unclear scope.

Stop Conditions

  • A slice cannot compile, test, or deploy independently.
  • A required product, architecture, validation, rollout, or scope decision is missing.
  • The implementation touches files outside the selected slice scope.
  • The coarse/single-PR path grows beyond the approved review risk.
